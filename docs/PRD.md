# PRD — Slack 클론 (Java / Spring Boot)

> 상태: **확정 (2026-11-20 사용자 동의).** 바꿔야 하는 기준은 먼저 묻는다.

## 1. 목적
- 이력서용 Java 미니 프로젝트. Slack의 핵심(채널 기반 실시간 메시징)을 만든다.
- 두 번째 목적: **Claude · OpenAI · 사용자가 한 팀으로 PR 리뷰를 거쳐 코드를 관리하는 경험**을 기록으로 남긴다.
- 세 번째 목적: AI 엔지니어 과정의 기술(CLAUDE.md, 하네스, 평가)을 Java 프로젝트에 적용한다.

## 2. 스택 (합의됨)
Java 21 · Spring Boot 4 · Gradle(Wrapper) · WebSocket(STOMP) · Spring Data JPA · Flyway · JUnit5 · ArchUnit
DB: 로컬 H2(PostgreSQL 모드), CI는 실제 PostgreSQL 서비스 컨테이너. 프론트는 단일 HTML/JS 최소 화면.

## 3. 만들 것 (MVP)
1. 회원가입 · 로그인
2. 채널 생성 · 목록 · 참여
3. 실시간 메시지 전송 · 수신 (WebSocket)
4. 메시지 이력 저장 · 조회
5. AI 스레드 요약봇 (마지막 단계)

## 4. 하지 않을 것 (지우거나 낮추지 않는다)
- DM, 스레드 답글 UI, 멘션, 파일 업로드, 검색, 알림, 다중 워크스페이스
- 다중 서버 메시지 전파(Redis 등), 운영 배포, 모바일 앱
- 프론트엔드 프레임워크(React 등)

## 5. 팀 운영 규칙
| 역할 | 담당 |
|---|---|
| 사용자 | 설계 · 승인 · 머지, 핵심 도메인 PR 직접 구현(4·5단계) |
| Claude | 나머지 구현, 사용자 PR 리뷰 |
| OpenAI | 모든 PR 리뷰 (GitHub Actions + OpenAI API) |

- 모든 변경은 `feature/*` 브랜치 → PR → 머지. `main`에 직접 push하지 않는다.
- 머지 조건: **CI 통과 + AI 리뷰 코멘트 응답/해결 + 사용자 승인**, 방식은 squash merge.
- 작성자 구분: 커밋 `Co-Authored-By`, PR 라벨 `by:claude` / `by:me`.
- 알려진 제약: 같은 계정이 올린 PR은 본인이 Approve 할 수 없다 → 저장소 설정 단계에서 필수 status check + 수동 머지로 대체할지 확인한다.

## 6. 단계와 "끝났다는 증거"
한 번에 한 단계만 진행한다. 증거는 실제로 실행한 결과로 보인다.

| 단계 | 내용 | 작성 | 끝났다는 증거 |
|---|---|---|---|
| 0 | 프로젝트 골격 (Initializr, 패키지 구조) | Claude | `./gradlew build` 성공, 앱이 뜨고 `/actuator/health` 가 UP, `domain`/`service`가 Spring Web을 import하지 않음을 검사하는 ArchUnit 테스트 1개 통과. (저장소는 1단계에서 만들며, 0단계 골격은 로컬에서 만들어 1단계에 첫 커밋으로 올린다) |
| 1 | GitHub 저장소 · 보호 브랜치 · CI · OpenAI 리뷰 Action | Claude + 사용자(Secrets) | 더미 PR에서 CI 통과, OpenAI 리뷰 코멘트가 달림 |
| 2 | 회원가입 · 로그인 | Claude | 가입 → 로그인 → 인증 필요한 API 호출 통합 테스트 통과, 비밀번호는 해시 저장 |
| 3 | 채널 | Claude | 채널 생성/참여/목록 테스트 통과, 미참여 채널 접근 거부 확인 |
| 4 | 실시간 메시지 | **사용자** | 클라이언트 2개가 같은 채널에서 송수신하는 테스트 통과, 비참여자는 수신 못함 |
| 5 | 메시지 이력 | **사용자** | 재시작 후에도 이력 조회, 페이지네이션 테스트 통과 |
| 6 | AI 요약봇 | Claude | 같은 입력으로 Claude · OpenAI 실호출 요약이 반환됨 (Fake는 테스트 전용) |
| 7 | 요약 평가 | Claude | 평가셋에서 두 모델을 같은 조건으로 비교한 측정값 표 |

## 7. 설계 원칙 (CLAUDE.md와 동일)
- 핵심 로직(`domain`, `service`)은 Spring Web · WebSocket을 모른다. ArchUnit 테스트로 강제한다.
- 외부 의존(LLM, 시계)은 인터페이스를 생성자로 주입한다. 요약은 `Summarizer` 인터페이스.
- LLM 결과는 정해진 형식(JSON 스키마)으로 받는다. 요약에 메시지 원문 외 사실을 넣지 않는다.
- 사용자 메시지는 프롬프트에서 태그로 감싸고, 태그 안 문장은 지시가 아니다.
- 바꿀 수 있는 값(모델 이름, 길이 한도)은 설정 파일에만 둔다.
- 비밀(API 키, DB 비밀번호)은 코드와 git에 넣지 않는다.

## 8. 평가 (6~7단계)
- Claude와 OpenAI가 같은 프롬프트 · 같은 입력을 받는다. 한쪽 전용 지시문을 만들지 않는다.
- 채점 기준은 고정한다. 숫자는 실제 호출 결과로만 보고한다.
- 평가 문장을 프롬프트 예시에 넣지 않는다.

## 9. 미정 (진행 중 하나씩 묻는다)
- 저장소 이름
- 요약봇이 쓸 모델 구조 (제안: 인터페이스 뒤에 Claude/OpenAI 둘 다)
- OpenAI 리뷰 모델과 월 비용 상한
- 리뷰 Action 구현 방식 (직접 작성한 스크립트 vs 기존 Action)
- 요약 대상 범위 (제안: "스레드"가 아니라 채널의 최근 N개 메시지. 6단계 전에 확정)
